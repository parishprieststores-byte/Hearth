2.0 P1 (documents, upload progress, retry; FREE plan, no Storage): a document button beside the photo button sends any file up to 5 MB except programs and scripts (.exe .apk .js .sh etc, blocked in the app only). The file is split into pieces of about 700 KB and stored as hidden chunk documents in the chat; the message then shows a file card with a type badge (PDF, DOC, XLS, ZIP...), name and size and a Download button with percent progress. Uploads show percent, resume from the failed piece with Retry, pause when offline and continue by themselves when the connection returns, and can be cancelled. A text, photo, voice or file message that the database rejects now appears above the message box as Not sent with Retry and Delete. Deleting a file message for everyone also removes its pieces. REQUIRES re-publishing firestore.rules (new chunks rule, new 'file' field).
Limits you should know: every download costs one database read per piece (about 10 for a 5 MB file) and each read also triggers a rules check, so heavy file use eats the free 50,000 reads/day and 1 GiB total storage; files are not previewed as thumbnails (type badge only); documents cannot be forwarded yet; files are not end-to-end encrypted and are not virus-scanned; videos work only as short clips under 5 MB; failed-send entries live in memory and vanish if you close the app.
Checks: 16 send a 200 KB PDF, see percent, other phone downloads and opens it. 17 send a 4 MB Word/Excel/ZIP file. 18 try a 6 MB file: refused. 19 try an .exe or .apk: refused. 20 turn off data mid-upload: shows Waiting; turn on: finishes. 21 delete a file message for everyone: card disappears. 22 publish rules but use an old app copy: file send fails with a clear message.

2.0 P2 (emoji, stickers, GIFs, voice calls; FREE plan). REQUIRES re-publishing firestore.rules (new calls collection, message fields st, gif, call).

GIFs need a free GIPHY key (developers.giphy.com): paste it once in the GIF tab; it stays on the device. Receiving a GIF loads it from GIPHY's servers. Only giphy.com media links are accepted by the rules.

Only people who already share a chat can ring each other.
Not built yet: group calls, video calls, speaker toggle, a separate Calls tab, animated stickers, ringing when the app is closed, a relay server, blocking spam callers.

2.0 P3C (exit and delete powers). REQUIRES re-publishing firestore.rules. Group chats: group admins (groups made since P0, or older groups after Set up admins) get Delete group in Group info, with a type-DELETE confirmation; it deletes messages and files in batches, then the group, for every member (members who have it open are told it was deleted). A sole admin who taps Leave group now picks a new admin first. Communities: the owner sees Transfer ownership (choose an admin; you become admin and can then Leave) and Delete community (type DELETE; removes posts, events, spaces, members, invite and listing). Other members' pointers to a deleted community are cleaned when they open it. Limits: deletes count as writes on the free plan (20,000 a day): very large histories are only partly deleted in one go (up to about 2,000 group messages and 2,000 posts or events per space per run) and any leftovers are unreachable but still stored; 'Delete group' is not offered for older groups until admins are set up; not run on devices; the ownership-transfer rule uses a batched check that is the part I am least sure of (untested).
